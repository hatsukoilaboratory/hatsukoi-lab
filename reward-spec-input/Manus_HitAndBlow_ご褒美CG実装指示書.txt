Hit & Blow ご褒美CG機能 実装指示書（Manus用）
================================================

■ 目的
既存の /mutual Hit & Blow ミニゲームに、ご褒美CG収集・閲覧・コンプリート特典を追加する。

今回の目的は単なるクリア報酬ではなく、
「振り返りで上達 → 次はご褒美ラインを狙う → CGを集める → コンプリート」
という周回動機を作ること。

既存のゲーム本体、HIT/BLOW判定、ヒント、履歴、振り返り、最善手アドバイス、
「先生との縁」、現在の戻り先保持などは壊さないこと。
既存機能の大規模な書き換えは避け、報酬機能を追加実装する。

--------------------------------------------------
1. 素材
--------------------------------------------------

配置先例:
  /mutual/assets/rewards/

通常報酬CG 9枚:
  reward_ai.webp
  reward_bokukko.webp
  reward_douki.webp
  reward_ginpatsu.webp
  reward_haishinsha.webp
  reward_koito.webp
  reward_kouhai.webp
  reward_mizuki.webp
  reward_natsu.webp

コンプリート特典:
  reward_narumi_complete.webp

全画像:
  800 x 1200
  WebP

重要:
各通常CGにはキャラクターのご褒美セリフが画像内にすでに入っている。
Web側で同じセリフをテキストとして重ねないこと。

reward_narumi_complete.webp にも
「せんせ！よく頑張りましたね♪」
の吹き出しが画像内に入っている。

--------------------------------------------------
2. ご褒美条件
--------------------------------------------------

【9人から4人を当てる select4】

1手:
  rank = LUCKY
  表示 = 豪運解決
  報酬 = 通常ご褒美CG9枚をすべて一括解放

2～4手:
  rank = MASTER_DETECTIVE
  表示 = 名探偵クリア
  報酬 = 未解放の通常CGからランダム1枚

5手:
  rank = REWARD_CLEAR
  表示 = ご褒美クリア
  報酬 = 未解放の通常CGからランダム1枚

6手以上:
  rank = NORMAL_CLEAR
  表示 = 通常クリア
  報酬 = なし


【9人から3人を当てる select3】

1手:
  rank = LUCKY
  表示 = 豪運解決
  報酬 = 通常ご褒美CG9枚をすべて一括解放

2～3手:
  rank = MASTER_DETECTIVE
  表示 = 名探偵クリア
  報酬 = 未解放の通常CGからランダム1枚

4手:
  rank = REWARD_CLEAR
  表示 = ご褒美クリア
  報酬 = 未解放の通常CGからランダム1枚

5手以上:
  rank = NORMAL_CLEAR
  表示 = 通常クリア
  報酬 = なし


判定関数のイメージ:

function getRewardResult(mode, clearTurns) {
  if (clearTurns === 1) {
    return { rank: "LUCKY", reward: "UNLOCK_ALL" };
  }

  if (mode === "select4") {
    if (clearTurns <= 4) {
      return { rank: "MASTER_DETECTIVE", reward: "UNLOCK_RANDOM_ONE" };
    }
    if (clearTurns === 5) {
      return { rank: "REWARD_CLEAR", reward: "UNLOCK_RANDOM_ONE" };
    }
    return { rank: "NORMAL_CLEAR", reward: null };
  }

  if (mode === "select3") {
    if (clearTurns <= 3) {
      return { rank: "MASTER_DETECTIVE", reward: "UNLOCK_RANDOM_ONE" };
    }
    if (clearTurns === 4) {
      return { rank: "REWARD_CLEAR", reward: "UNLOCK_RANDOM_ONE" };
    }
    return { rank: "NORMAL_CLEAR", reward: null };
  }
}

--------------------------------------------------
3. 重複排出は禁止
--------------------------------------------------

通常報酬CG9枚に対して、同じCGを2回「新規獲得」させない。

未解放CGが1枚以上ある場合:
  → 未解放CGだけを候補にしてランダム抽選する。

例:
  9枚中6枚取得済みなら、残り3枚だけからランダム1枚を選ぶ。

すでに9枚すべて取得済みの場合:
  → 新規解放処理は行わない。
  → ご褒美ライン達成の演出自体は表示してよい。
  → 必要なら取得済み9枚からランダム1枚を「再表示」してよい。
  → 再表示は新規取得として記録しない。

--------------------------------------------------
4. 永続保存
--------------------------------------------------

取得状態はリロード、ブラウザ再起動、再挑戦後も残す。

既存の保存データを壊さない独立キーを使用すること。

例:
  mutualRewardUnlockedV1
  mutualRewardCompleteUnlockedV1
  mutualRewardCompleteSeenV1

通常CGはIDで管理する。

例:

const REWARD_CGS = [
  { id:"ai", file:"reward_ai.webp", name:"アイちゃん" },
  { id:"bokukko", file:"reward_bokukko.webp", name:"ボクっ娘幼馴染ちゃん" },

--------------------------------------------------
5. クリア後の基本表示順
--------------------------------------------------

ゲームクリア
↓
クリア手数判定
↓
クリア評価演出
↓
ご褒美条件達成ならCG解放判定
↓
新規CGを1枚表示
↓
捜査振り返り・最善手アドバイス

通常CGの新規獲得時は、
「NEW! ご褒美CG解放」
など、新規取得だと分かる表示を付ける。

CGそのものを十分大きく見せること。
縦長2:3なので、スマホでは画面内に収まるよう
max-height と object-fit: contain を使用する。
画像を切り抜かないこと。

--------------------------------------------------
6. 通常ご褒美未達時
--------------------------------------------------

CGは出さない。

例:
select4を6手でクリア:
  「惜しいっス！ あと1手縮めればご褒美だったっス！」

select3を5手でクリア:
  「惜しいっス！ あと1手縮めればご褒美だったっス！」

その後、既存の振り返り・最善手アドバイスへ自然につなぐ。

「あと何手縮めればご褒美だったか」は
modeごとの条件から自動計算し、ハードコードしすぎないこと。

--------------------------------------------------
7. 豪運解決
--------------------------------------------------

1手目で正解した場合は通常の名探偵評価と分ける。

表示:
  豪 運 解 決
  または LUCKY SOLVE!!

鳴海の演出例:
  「えっ！？ 先生、まだ何も推理してないっスよね！？」
  「これ……実力っていうか豪運っス！！」

道庭:
  「……推理する前に事件が終わった。」

続けて:
  豪運ボーナス！
  ご褒美CG ALL UNLOCK！

通常CG9枚を一括解放する。

9枚すべてが解放された結果、
未解放だったコンプリート特典も同時に条件成立する。
ただし通常CG9枚を1枚ずつ連続表示する必要はない。

豪運演出
↓
ALL UNLOCK表示
↓
コンプリート演出
の順でよい。

--------------------------------------------------
8. ご褒美CGギャラリー
--------------------------------------------------

取得したCGをいつでも再閲覧できる画面を追加する。

画面名:
  ご褒美CG一覧

通常CG9枠 + コンプリート特典1枠。

通常9枠:
  解放済み → サムネイル表示、タップで大きく表示
  未解放   → ロック表示 / シルエット等

通常CGはキャラ名を表示してよい。

進捗表示例:
  ご褒美CG 5 / 9

コンプリート特典枠:
  通常9枚を集めるまでは「???」「SECRET」等で伏せる。
  鳴海の名前や画像を事前に見せすぎないこと。
  解放後は「鳴海の差し入れ」として表示してよい。

コンプリート特典は通常9枚とは別枠なので、
通常進捗の分母は9のままでよい。

--------------------------------------------------
9. ギャラリーへの導線・戻り先
--------------------------------------------------

既存の「先生との縁」と同様に、
どこから入ったかを保持して戻れるようにする。

タイトル画面から入った場合:
  戻る文言 = 「タイトルへ戻る」

ゲーム進行中から入った場合:
  戻る文言 = 「推理に戻る」
  現在のスロット、履歴、ヒント、正解、手数等を破棄しない。

クリア結果画面から入った場合:
  戻る文言 = 「結果に戻る」
  結果画面を作り直さず、そのまま戻る。

既存の origin-aware return の仕組みがあるなら再利用する。

--------------------------------------------------
10. コンプリート条件
--------------------------------------------------

通常ご褒美CG9枚をすべて解放した瞬間、
鳴海のコンプリート特典を自動解放する。

対象:
  reward_narumi_complete.webp

通常のランダム抽選には絶対に含めない。

「9枚目を通常クリアで取得した時」と
「1手豪運で9枚一括解放された時」の両方で成立する。

一度解放した後は再度コンプリート解放演出を繰り返さない。
ギャラリーでは何度でも閲覧可能。

--------------------------------------------------
11. コンプリート演出
--------------------------------------------------

通常クリアで9枚目を取得した場合:

9枚目の通常ご褒美CGを表示
↓
ユーザーが閉じる / 次へ
↓
COMPLETE演出
↓
鳴海のセリフ
↓
鳴海コンプリートCG表示
↓
結果・振り返りへ戻る

見出し:
  ご褒美CGコンプリート！

鳴海:
  「言ったじゃないスか」
  「問題に入ってない差し入れがあるって」
  「……これ、あたしからっス」

3つ目のセリフのあとに
reward_narumi_complete.webp
を表示する。

この3セリフはWeb側の演出テキスト。
CG画像内には別途
「せんせ！よく頑張りましたね♪」
が焼き込まれているので、そのままでよい。

ギャラリーでの名称:
  鳴海の差し入れ

説明を付ける場合:
  「みんなのご褒美を集めた先生へ。鳴海からの、最後の差し入れ。」

--------------------------------------------------
12. 全CG取得後の再プレイ
--------------------------------------------------

通常9枚 + 鳴海をすべて取得済みでもゲームは通常通り遊べる。

ご褒美ライン達成時:
  「ご褒美CGは全部集め終わってるっス！ 完全制覇っスね！」
等を表示。

必要なら通常9枚の中からランダム1枚を再表示してよい。
ただし解放データや取得数は増やさない。

コンプリート演出は再発火させない。

--------------------------------------------------
13. ヒント利用について
--------------------------------------------------

現時点ではヒント使用の有無はCG獲得条件に含めない。

判定基準は「クリア手数」のみ。

既存の
・ヒント最大3回
・ノーヒント記録
等はそのまま維持する。

将来バランス調整できるよう、
報酬条件を1か所の設定値にまとめると望ましい。

例:
const REWARD_LIMIT = {
  select3: 4,
  select4: 5
};

--------------------------------------------------
14. UIの注意
--------------------------------------------------

・スマホを最優先する。
・390x844程度でもCG全体が見えること。
・CG表示モーダルで画面外へはみ出さない。
・画像は object-fit: contain。
・閉じる / 次へボタンを親指で押しやすい位置に置く。
・画像読み込み中は簡単なローディング表示を出す。
・ギャラリー全画像を初回起動時にフルロードしない。
・ギャラリーのサムネは loading="lazy" 等で遅延読込してよい。
・未取得CGの画像URLをDOMへ不用意に埋め込み、簡単にネタバレ表示させないこと。
  完全な秘匿は不要だが、通常UIからは見えないようにする。

--------------------------------------------------
15. 既存機能を壊さない
--------------------------------------------------

今回の修正で以下を必ず保持する。

・3人 / 4人モード
・HIT / BLOW判定
・判定直後の結果表示
・同一回答の連続送信防止
・回答変更後の再判定
・履歴
・ヒント最大3回
・ヒント表示時のスクロール
・ノーヒント記録
・「先生との縁」
・「先生との縁」からのorigin別戻り
・クリア結果
・振り返り
・最善手アドバイス
・ベストスコア等、現在保存されている情報
・Xシェア等、既存導線

報酬機能のためにゲームの判定アルゴリズムを変更しない。

--------------------------------------------------
16. テスト項目
--------------------------------------------------

最低限、以下を実機またはモバイル幅で確認する。

A. select3
  ・4手クリア → 未取得CGが1枚解放
  ・5手クリア → CGなし
  ・1手クリア → 9枚一括解放 + 鳴海解放

B. select4
  ・5手クリア → 未取得CGが1枚解放
  ・6手クリア → CGなし
  ・1手クリア → 9枚一括解放 + 鳴海解放

C. 重複
  ・同じCGが新規取得として2回出ない
  ・8/9状態から成功 → 残り1枚が必ず出る

D. コンプリート
  ・9枚目取得後に鳴海演出が1回だけ出る
  ・再読込しても鳴海取得状態が残る
  ・再プレイしてもコンプリート演出が再発火しない

E. ギャラリー
  ・解放済みCGをタップで再閲覧できる
  ・未解放CGは見えない
  ・SECRET枠はコンプ後に鳴海へ変わる
  ・タイトル / 推理中 / 結果から正しい戻り先へ戻れる
  ・推理中にギャラリーへ入ってもゲーム状態が消えない

F. 既存ゲーム回帰テスト
  ・判定
  ・履歴
  ・ヒント
  ・振り返り
  ・先生との縁
  ・保存状態
  が以前と同じように動作する。

G. 表示
  ・iPhone相当 390x844
  ・CGが切れずに見える
  ・縦スクロールが不自然に飛ばない
  ・モーダルを閉じた後に元の位置へ戻れる
